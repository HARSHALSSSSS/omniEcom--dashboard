# Frontend integration map (frontend/src/pages vs backend/docs/api/openapi.json)

Sources: openapi.json (683 operations, verified with a lookup script), the backend route and plugin code where openapi hides detail, integration docs 01 and 02, and the frontend pages, types, api, hooks and mocks. Paths are relative to `/api/v1` unless they start with `/health`. "Perm" is the backend permission (`authenticated` means any signed-in user). Sections 1 to 3 were written first-hand. Sections 4 to 12 were researched by four slice reviewers against openapi and the page JSX, and I spot-checked their shared conventions. Where a field is marked UNVERIFIED, openapi only says "object". Notes to the integrator are inline.

### 0.2 Auth flow
| Step | Call | Notes |
|---|---|---|
| Register | `POST /auth/register` (public). Body `{businessName 2..120, legalName?, fullName 2..120, email, password 10..128, phone? 7..20, gstin?}`. 201 `data{user{id,email,fullName,userType,vendorId,roles[],emailVerified,status,lastLoginAt}, vendor{id,displayName,slug,status}, emailVerificationRequired}` | **Returns no tokens.** Call login immediately afterwards. Frontend password rule is min 8 (+letter+digit): change to min 10 (and max 128). Sign-up form needs no `businessType` and no city here. |
| Login | `POST /auth/login` (public). Body `{email, password}`. 200 `data{tokenType, accessToken, expiresIn (seconds, access TTL 15 min), refreshToken, sessionId, user{...}, vendor{...}|null}` | Store `accessToken` in memory. The `refreshToken` is opaque, single-use, and must be persisted (sessionStorage or localStorage) for reloads because there is no cookie. Account locks for 15 minutes after repeated failures (`ACCOUNT_LOCKED` 423). 401 `INVALID_CREDENTIALS` must NOT go through the refresh branch. |
| Refresh | `POST /auth/refresh` (public). Body `{refreshToken}`. Same response as login (new pair + user + vendor) | **Rotation: every use invalidates the old token, and presenting an already-used token revokes the whole session.** Implement a single in-flight refresh promise shared by all parallel 401s, and persist the new refresh token BEFORE retrying requests. Refresh only on 401 `TOKEN_EXPIRED` (or `UNAUTHENTICATED`) for non-auth URLs, one retry per request, never refresh when the failing URL is `/auth/*`. On refresh failure clear state and go to `/signin`. Current `client.ts` sends `{}` and expects a cookie: rewrite. Response field is `data.accessToken` (same path as today). |
| Logout | `POST /auth/logout` (authenticated). `POST /auth/logout-all` revokes all sessions | Rename from signout. Clear token, store, and query cache even if the call fails. |
| Verify e-mail | `POST /auth/verify-email {token}` (public); `POST /auth/resend-verification` (authenticated, 202) | Needs a `/verify-email` page that reads `?token=`. Unverified users get 403 `EMAIL_NOT_VERIFIED` on marketplace connect (see Hub). |
| Forgot / reset | `POST /auth/forgot-password {email}` (always 202), `POST /auth/reset-password {token (20..200 chars), password}` | SignIn "Forgot password?" is an `alert`; add pages. |
| Profile | `GET/PATCH /me/profile {fullName}`, `POST /me/change-password {currentPassword,newPassword}` (signs out other sessions), `GET /me/sessions`, `DELETE /me/sessions/{id}` | Not on any current page. |

**Bootstrap sequence (replaces the persisted fake session in `workspace.store`: `isAuthenticated:true`, `onboardingComplete:true`, DEFAULT_USER):**
1. On app start, if a stored `refreshToken` exists: `POST /auth/refresh` (single-flight). If none: unauthenticated.
2. `GET /me` (authenticated) gives `{userId,userType,vendorId,roles[],permissions[]}`. Store `permissions` as a `Set`.
3. In parallel: `GET /workspace/shell` (user, business, badges, features, inventoryMode) and `GET /onboarding` (needs `onboarding:read`).
4. Guards: `ProtectedRoute(requireOnboarding)` waits for the bootstrap (render the `PageLoader`). `requireOnboarding` uses `onboarding.status==='completed'`. Incomplete: redirect to `/onboarding/{resumeStep}` (keys equal the route slugs `business|channels|products|inventory|fulfillment|ready`). `PublicOnlyRoute` redirects authenticated users the same way. Remove persist for `isAuthenticated`, `user`, `onboardingComplete`, `needsAttentionCount` from `workspace.store` (persist at most the refresh token).
5. After login/register-then-login, run steps 2 to 3 before navigating. Honour `location.state.from` only after onboarding is complete.

**Permissions (`GET /me` permissions[]):** replace `useCan`'s role map (owner/admin/seller/viewer, default-allow) with permission strings: `useCan('products:write')`. Backend roles (`GET /roles`, perm `roles:read`): `vendor_admin` (everything in the vendor), `vendor_staff` (operations; NO `vendors:write`, `users:*`, `marketplace_accounts:write`, `ai:use`, `automation:*`, `onboarding:write`, `pricing:write`, `pricing:approve`, `procurement:approve`, `returns:refund`, `shipping:configure`, `warehouses:admin`, `products:delete`, `billing:*`), `vendor_viewer` (only `*:read`; no `ai:use`, no `users:read`). Staff does have `reports:write`, `promotions:*`, `procurement:read|write`, `imports:*`, `issues:*`. Hide or disable controls the user lacks. A 403 body is `error.code FORBIDDEN` with `details.requiredPermission`. A resource of another tenant is a 404, never a 403. Sidebar: filter `NAV_GROUPS` by read permission (Orders `orders:read`, Reports `reports:read`, AI `ai:use`, Automation `automation:read`, Pricing `pricing:read`, Promotions `promotions:read`, Procurement `procurement:read`, Intelligence `analytics:read`). `Sidebar` role label comes from `shell.user.roleLabel`.

**Feature flags:** `GET /features/me` returns `data` as a flat `{ "ai.enabled": bool, "automation.enabled": bool, ... }`; `GET /workspace/shell` also carries `features` (record of booleans). AI and Automation routes answer 403 `FORBIDDEN` with `details.rule="feature_disabled"` and `details.flag` when off (AI also when the business turns AI off in `/ai/settings`). Hide the nav items and show a "not enabled" state. `VITE_ENABLE_AI` / `VITE_ENABLE_AUTOMATION` env flags become secondary.

| Codes | 400 `VALIDATION_FAILED`,`BAD_REQUEST`; 401 `UNAUTHENTICATED`,`TOKEN_INVALID`,`TOKEN_EXPIRED`,`INVALID_CREDENTIALS`; 403 `FORBIDDEN`,`TENANT_SUSPENDED`,`EMAIL_NOT_VERIFIED`; 404 `NOT_FOUND`; 409 `CONFLICT`,`VERSION_CONFLICT`,`IDEMPOTENCY_IN_PROGRESS`,`ACCOUNT_NOT_CONNECTED`,`INSUFFICIENT_STOCK`,`INVALID_STATE`; 413 `PAYLOAD_TOO_LARGE`; 415 `UNSUPPORTED_MEDIA_TYPE`; 422 `IDEMPOTENCY_KEY_REUSED`,`CAPABILITY_UNSUPPORTED`,`LISTING_NOT_READY`; 423 `ACCOUNT_LOCKED`; 428 `PRECONDITION_REQUIRED`; 429 `RATE_LIMITED` (+`Retry-After`); 502 `UPSTREAM_ERROR` (`details{marketplace,kind,code,action}`); 503 `SERVICE_UNAVAILABLE`. | Central toast mapping. `TENANT_SUSPENDED`: lock screen. 429: honour `Retry-After`. |
| Bulk | Always HTTP 200 with per-item `results[]` and `summary` (partial success). | Never treat 200 as total success. |
| Async | 202 plus a job. | Money | Integer minor units, fields `*Minor` (+ `currency`), rates `*Bps` (basis points, 100 bps = 1%, `gstRateBps 1800` = 18%). | `formatINR(paise)` already divides by 100: pass minor units and rename frontend vars (`totalAmount` etc. are really minor units; mocks are in rupees, which makes mock screens 100x too small). | Dates | ISO-8601 UTC strings; business time zone in `shell.business.timezone` (Asia/Kolkata default); dashboards `asOf` is `YYYY-MM-DD` in that zone. | Format with the business timezone. |
| Marketplace codes | Backend `amazon_in, flipkart, myntra, snapdeal, shopify, meesho, mock`. Frontend `amazon` must map to `amazon_in` (both directions). | Deep links | Backend hrefs inside notifications, issues, search, dashboard: `/orders/{id}`, `/orders?attention=true`, `/orders?filter[sla]=at_risk`, `/inventory`, `/inventory?health=low`, `/inventory/variants/{id}`, `/listings?status=attention`, `/listings?filter[status]=needs_fix`, `/listings?filter[contentState]=failed|needs_review`, `/channels`, `/channels/{id}`, `/sync/jobs/{id}`, `/products/{id}`, `/returns?filter[status]=requested|received`, `/returns?filter[refund]=failed`, `/shipping?filter[...]`, `/shipping/methods`, `/procurement`, `/needs-attention`, `/marketplace-hub/health`. | Write `toAppRoute(href)`: `/channels[/id]` to `/marketplace-hub` (or `/marketplace-hub/health`), `/sync/jobs/*` to `/marketplace-hub/health`, `/shipping/methods` to `/shipping`; routes `/orders/:id` and `/inventory/variants/:id` do not exist: add query-param handling (`/orders?orderId=`, `/inventory?variantId=`) or drawers. ### 11.E AutomationPage (`/automation`)
All behind `automation.enabled` (+`automation:read|write`; staff and viewer have neither). Existing endpoints: `GET /automation/catalog` (`triggers[{event,description,facts}]`, `actions[{type,description,triggers,reversible}]`, `operators`), `GET /automation/rules` (array; `filter[status] draft|active|disabled`,`filter[trigger]`), `POST /automation/rules {name,description?,triggerEvent,conditions?,action{type,params?},mode auto|approval,status?}` (created as `draft` unless `status:"active"`), `PATCH /automation/rules/{id}`, `POST .../activate|disable`, `DELETE`, `POST .../test {payload}`, `GET /automation/executions` (`filter[status] executed|pending_approval|rejected|failed|skipped|rolled_back`,`filter[ruleId]`,`limit<=200`, no paging), `POST /automation/executions/{id}/approve` (200 may carry `status:"failed"`), `.../reject {note?}`, `.../rollback`. **`/automation/overview`, `/automation/runs`, `/automation/approvals/*` (frontend guesses) do not exist in openapi**; the backend has unexposed views (overview, approvals, runs with `ruleName,proposedAction,financialImpact,summary,durationMs`) not yet registered as routes, and rule DTO extras (`runsCount`, `lastRunAt`, `requiresExplicitApproval`) are stripped by the response schema: confirm with the backend owner before locking types; until then derive KPIs from rules and executions. Vocabulary: UI `stock_below_threshold` to `inventory.low_stock`, `order_sla_risk` to `order.sla_at_risk`, `buybox_price_drop` to `price.competitor_lower`, `listing_sync_failure` to `sync.failed|sync.dead_lettered|listing.failed`; actions `draft_purchase_order` (trigger low_stock only), `adjust_channel_price` (trigger price.competitor_lower only, creates a price proposal), `notify_channel_slack` to `notify` (in-app/email, not Slack); filter actions by the selected trigger from the catalog (else 400). Status: UI `paused` = `disabled`, plus `draft`. Execution to UI: `executed|rolled_back` success, `pending_approval` awaiting, `failed|skipped|rejected` failed. Errors: 403 flag/permission, 400 unknown trigger (`details.allowed`), 409 `INVALID_STATE` on approve/reject when not pending, delete refused if the rule ran.
