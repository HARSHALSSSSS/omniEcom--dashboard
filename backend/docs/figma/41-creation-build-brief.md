# Product creation flow: decisions and build brief

Study: `40-product-creation-flow-analysis.md` (the 6 screens of Figma "Product creation flow"). Shared engineering rules: `20-build-brief.md` (ownership, conventions, tests, final report) still apply, except where this file says otherwise.
This file: (1) decisions that answer the open questions the way large commerce platforms handle them, (2) exact behaviour per field, (3) the API to build per work package.

## 0. Environment warnings (learned the hard way)
* **Never write `\uXXXX` escape sequences through shell heredocs or tool inputs**: the tooling turns them into literal characters and breaks the file (e.g. regex character classes). Use `\xNN`, `String.fromCharCode`, or code-point comparisons (`cp >= 0x200b`) instead.
* Do not use shell heredocs with quotes for code; use the Write/Edit tools. No git commands.
* Run only your own tests (`--maxWorkers=1`), typecheck only your module (`pnpm --filter @oms/mod-<name> typecheck`).

## 1. Decision log (how established platforms do it, and what we do)
| # | Question | What the market does | Our decision |
|---|---|---|---|
| D1 | Can a draft exist without a SKU? | Shopify saves a draft with only a title; Akeneo (PIM) demands an identifier at creation; Amazon requires a SKU only when listing | **Draft needs only a title (1-200 chars).** If no master code is given we generate `DRAFT-XXXXXXXX` (8 chars, A-Z0-9) flagged `codeIsPlaceholder`. **Continue** requires a real, unique master code. |
| D2 | SKU uniqueness | Amazon / Flipkart treat SKUs case-insensitively inside a seller account; Shopify warns only | **Master code is unique per business ignoring case** (DB unique index on `lower(product_code)`). Equality with another product's *variant SKU* is a **warning** (`similar`), not an error. |
| D3 | Readiness / completeness | Akeneo: completeness = filled required / total required per channel; Shopify: setup checklist; Amazon: listing-quality score | **Checklist of 8 items, equal weight; percent = round(100 * done / 8).** (Matches the main design: 3 done = 38%. The 50% on the upload screen in Figma is mock data: with name, category, type, SKU and brand done the checklist is 63%, we do not fake numbers.) Required items = blockers for publishing; recommended items never block. |
| D4 | Rich description | Shopify stores sanitised HTML; Amazon wants plain text + bullets | **Store sanitised HTML subset in `description_html` and always keep the plain-text form in `description`** (what marketplaces and existing listing code read). Limit **2,000 characters of plain text**. Allowed markup: p, br, strong/b, em/i, ul, ol, li, a[href=http(s)/mailto]. Sanitiser: `modules/catalog/src/description.ts` (given, must be hardened + fully tested). |
| D5 | Placeholder image | Amazon rejects placeholder images; Shopify shows its own empty-state image | **Placeholder allowed while drafting** (counts as an image in the checklist, state `placeholder`) **but it always blocks publishing** ("Replace the placeholder image before publishing"). Generated server-side as an SVG; a real upload replaces it automatically. User-uploaded SVG stays forbidden. |
| D6 | Brand | Amazon Brand Registry (approved brands), Shopify free text "vendor", PIMs use a reference list | **Managed per-business brand list.** A brand typed on a product is added **unconfirmed**; it becomes **confirmed** when the seller confirms it, when it is created explicitly in the brand list, or when picked from confirmed brands. Readiness tag `confirm` while the product's brand is unconfirmed. Names unique ignoring case/whitespace (1-80 chars). |
| D7 | Product vs package dimensions | Amazon separates *item* dimensions from *package* dimensions; Shopify keeps weight on variants | **Dimensions and weight live on the product (item, not package) as the design says**; variants may override and inherit the product values when empty. Package/shipping dimensions stay variant-level (later flows). Stored in mm and grams; API accepts and returns display units cm / kg, plus the canonical mm / g. |
| D8 | "Product category" second select (Screen 2, placeholder reads "Select material") | Shopify has both a standard product category (taxonomy) and a merchant category/type | **Interpreted as the seller's "standard product category"**: optional free text with suggestions from values already used (max 120 chars), stored in `standard_category`. **This is an assumption about an inconsistent design; flagged in the final report.** The merchant category tree (`categoryId`) is the required "Category". |
| D9 | Custom attributes | Shopify metafields, Akeneo attributes, Amazon "additional attributes" | **Free-form name/value pairs on the product** (`custom_attributes`): max 20, name 1-60 chars, value 1-250 chars, names unique ignoring case, each has `confirmed` (seller confirms facts before they are sent to listings; unconfirmed values are never sent). Promotion to real attribute definitions is out of scope. |
| D10 | Drafts and autosave | Shopify autosaves every change; Google-style "Last saved" | **Explicit `Save draft` + client autosave through the same PATCH with an optimistic `version`**; server returns `savedAt`; stale version -> 409 `VERSION_CONFLICT` with the current version. Draft products count toward plan limits like any product. |
| D11 | Discard | Shopify deletes a draft | **Discard = soft delete of a draft** (only `status = draft`, no stock, no listings, no order references); active/archived products cannot be discarded here. |
| D12 | AI copy | Shopify Magic / Amazon "generate listing": show a preview, human applies | **Suggest -> preview -> Apply / Dismiss.** Deterministic rules provider behind a provider interface (an LLM can be plugged in later); grounded **only** on facts that exist on the product; never invents features; rate-limited; respects the `ai.enabled` flag and the business AI settings; every suggestion and decision is stored and audited. |
| D13 | Images | Shopify allows 250 images, Amazon 9 (+video); marketplaces want >= 500-1000 px | **Max 20 product images per product**; hard minimum **200 px** on the shorter side (rejected), **warning below 1000 px** on the longer side (`low_resolution`); real MIME check by magic bytes (jpeg, png, webp, gif); max 25 MB (existing). First confirmed real image becomes primary. |
| D14 | HSN / GST | India GST slabs 0, 5, 12, 18, 28 % (plus special 0.25 %, 3 %) | HSN: digits only, length 4, 6 or 8. GST: any value 0-28 % in basis points, with the standard slabs offered in `form-options`. |
| D15 | Wizard steps | Shopify: product -> variants -> inventory | Chain `basic -> variants -> inventory -> listings -> channels`; only `basic` is designed. **Continue (basic) marks `basic` complete and moves `currentStep` to `variants`**; the other steps are tracked in `product_creation.completed_steps` but have no screens yet. |
| D16 | Master SKU "Verify" tag | Amazon verifies SKU availability before saving | **`verify`** = a real code that has not been checked for uniqueness since it last changed (`sku_verified_code != code`). `sku-check`/`validate-step` with a `productId` records the verified code. `duplicate` = the candidate code conflicts with another product. |

Anything not covered here: follow the existing code conventions, pick the safest option, and list it in your final report under "assumptions".

## 2. Field rules (single source of truth)
| Field (API) | Rule |
|---|---|
| `title` | draft: 1-200; continue/active: 3-200; trimmed; collapse inner whitespace |
| `productCode` (Master SKU) | pattern `^[A-Za-z0-9][A-Za-z0-9._\-/]*$`, 1-64; unique ignoring case (excluding itself); placeholder `DRAFT-XXXXXXXX` allowed only for drafts; cannot be changed to a placeholder pattern by the user (400) |
| `productType` | physical / digital / service (default physical) |
| `categoryId` | must exist in the business and not be deleted |
| `brand` | 1-80 chars, whitespace collapsed; upserted into `brands` (unconfirmed unless it already exists confirmed) |
| `description` (plain) / `descriptionHtml` | send either; server sanitises, stores both; plain-text length <= 2000 characters (counts code points); over limit -> 400 `description_too_long` with the counted length |
| `countryOfOrigin` | ISO 3166-1 alpha-2, upper-case, from the built-in country list |
| `dimensions` | `{ length, width, height, unit: 'cm'|'mm'|'in' }` (all three or none); each > 0; stored as integer mm (round half up); max 100,000 mm each |
| `weight` | `{ value, unit: 'kg'|'g'|'lb' }`; > 0; stored as integer grams; max 10,000,000 g |
| `material` | 1-80 chars |
| `standardCategory` | 1-120 chars |
| `gstRateBps` | integer 0-2800 |
| `hsnCode` | digits only, length 4, 6 or 8 |
| `customAttributes` | see D9; replacing the whole list on each save |
| `tags` | existing rules |
Responses expose both canonical and display values: `dimensions: { length, width, height, unit: 'cm' }`, `dimensionsMm`, `weight: { value, unit: 'kg' }`, `weightGrams` (null when unset).

## 3. Creation readiness (used by the right-hand panel)
Items (key -> rule). **Required**: `product_name` (title >= 3 chars), `category` (categoryId set), `product_type` (always set; done), `primary_image`, `master_sku`. **Recommended**: `description`, `brand`, `attributes`.
States: `done | pending | verify | confirm | duplicate | uploading | placeholder`.
* `primary_image`: `done` (real uploaded primary image), `placeholder` (placeholder is primary: counts as done for the percent, remains a blocker), `uploading` (a `pending_upload` product image exists, created < 30 min ago, and no ready primary), else `pending`.
* `master_sku`: `pending` (placeholder code or empty), `duplicate` (candidate conflicts), `verify` (real code, not yet verified), `done` (real, unique, verified).
* `brand`: `pending` (empty), `confirm` (entered but unconfirmed), `done` (confirmed).
* `attributes`: `done` when at least one custom attribute exists or the category's required attribute values are all set (existing category-attribute logic); otherwise `pending`.
* `description`: `done` when the plain text has >= 1 character.
Percent = round(100 * (#done + #placeholder) / 8). `blockers` = required items in `pending | duplicate | uploading | placeholder` **except** `master_sku` in state `verify` and `product_type`; each blocker `{ key, state, message, fixTarget: 'primary_image' | 'master_sku' | 'category' | 'product_name' }` with the messages used in the design ("Add a primary image before publishing this product to marketplaces.", "Primary image is uploading. Publication stays blocked until the upload completes.", "Resolve the duplicate SKU to continue.", "Replace the placeholder image before publishing."). `hint` strings for tags ("SKU and brand are entered; circles indicate pending verification or confirmation, not missing values.").
`channels`: the business's connected channels `[{ code, name }]` (active marketplace accounts) for "Where this information goes", plus `chain: ['Product','Variants','Inventory','Listings','Channels']`.
The stateless preview endpoint evaluates **unsaved form values** (including a candidate master code), so the duplicate state is visible before saving.

## 4. API to build
All under `/api/v1`, `products:read` for reads, `products:write` for writes unless stated. List responses use the repo conventions; keep every existing endpoint working.

### Work package CORE (owner: `modules/catalog/**` except the AI file)
Files: new `creation.ts`, `creation-routes.ts` (stub exists and is already registered), `creation-readiness.ts`, `brands.ts`, `form-options.ts`, `physical.ts` (unit conversion + validation), `countries.ts`, extend `schemas.ts` / `service.ts` / `routes.ts` carefully (additive), harden `description.ts`.
1. Product DTO/inputs: add `descriptionHtml`, `dimensions`, `dimensionsMm`, `weight`, `weightGrams`, `material`, `standardCategory`, `customAttributes` to create / patch / get (existing `POST /products`, `PATCH /products/{id}`, `GET /products/{id}`, catalog list items stay compatible: additive fields only). Variants: when a variant has no dimensions / weight the **response** carries `effectiveDimensionsMm` / `effectiveWeightGrams` from the product.
2. `GET /products/form-options`: `{ productTypes, gstSlabs: [{ bps, label }], countries: [{ code, name }] (India first, then A-Z), materials: [{ value, label }] (a curated common list + values already used by the business), units: { dimension: 'cm', weight: 'kg', accepted: {...} }, limits: { titleMin/Max, descriptionMaxChars: 2000, customAttributes: { max: 20, nameMax: 60, valueMax: 250 }, brandMax: 80, codeMax: 64, hsnLengths: [4,6,8] }, image: { maxBytes, mimeTypes, maxPerProduct: 20, minShortSidePx: 200, recommendedLongSidePx: 1000 } }` and `GET /products/standard-categories?q=&limit=` (distinct used values, prefix/contains match).
3. Brands: `GET /brands?q=&confirmed=&limit=` (confirmed first, then alphabetical), `POST /brands { name }` (explicit create = confirmed; 409 on duplicate ignoring case/whitespace with the existing brand returned in `details`), `POST /brands/{id}/confirm`, `DELETE /brands/{id}` (409 `in_use` when any live product uses it). Saving a product with a brand upserts it unconfirmed (and keeps `products.brand` text in sync with the canonical spelling of an existing brand).
4. SKU check: `GET /products/sku-check?code=&excludeProductId=` -> `{ code, normalized, valid, reason?, available, conflict: { type: 'product', id, title, code } | null, similar: [{ type: 'variant', sku, productId }], suggestion }` (suggestion = next free `CODE-2`, `CODE-3`...); `POST /products/{id}/sku/verify { code }` records `sku_verified_code` when available (409 `duplicate` otherwise).
5. Drafts: `POST /products/drafts` (title required, everything else optional per section 2; returns the creation DTO), `PATCH /products/{id}/draft` (partial, **`version` required**, only for `status = draft`, 409 `not_a_draft`), `GET /products/{id}/creation` (creation DTO), `GET /products/drafts` [paged: q, sort -savedAt; row: id, title, code, thumbnailUrl, savedAt, readinessPercent, currentStep], `DELETE /products/{id}/draft` (discard rules D11).
   **Creation DTO**: `{ product (editor view incl. new fields), creation: { currentStep, completedSteps, savedAt, version, codeIsPlaceholder }, readiness }`.
6. Readiness: `GET /products/{id}/creation-readiness` and stateless `POST /products/creation-readiness { productId?, values: {...unsaved form fields incl. productCode, title, categoryId, productType, brand, description/descriptionHtml, customAttributes} }` returning `{ percent, required: [{ key, label, state, tag? }], recommended: [...], blockers, hints, channels, chain }`.
7. Step validation: `POST /products/{id}/validate-step { step: 'basic', values? }` -> `{ valid, errors: [{ field, code, message }], warnings: [{ field, code, message }], readiness }` (**no writes except recording the verified SKU**); `POST /products/{id}/creation/continue { step: 'basic', version, values? }`: applies `values` as a patch (optimistic version), validates **only the basic step** (required: title >= 3, categoryId, productType, real unique code; field rules; description limit), on success marks `basic` completed, sets `currentStep = 'variants'`, returns the creation DTO; on failure 422 `VALIDATION_FAILED` with the same `errors`, **the draft values are still saved** (drafts can always be saved: "Draft saving is available even when this step needs a correction").
   Duplicate code on any save -> 409 `CONFLICT` with `details: { rule: 'duplicate_product_code', field: 'productCode', conflict: {...} }`.
8. Audit + outbox: `product.created` (existing), `product.updated`, `product.draft_saved` (audit only), `product.draft_discarded`, `brand.created|confirmed|deleted`.

### Work package AI (owner: `modules/catalog/src/ai-description*.ts`, the already-registered stub `ai-description-routes.ts`)
1. `POST /products/{id}/ai/description { mode: 'rewrite'|'concise'|'benefits', text? }` (text = the current editor content, may be unsaved; defaults to the saved description) -> `{ id, mode, text, html, basis: ['name','category',...], needsFacts, status: 'suggested', applied: false, note, createdAt }`. Guardrails: product must be draft or active; feature flag `ai.enabled` on for the business and the business AI settings enabled (else 403 `feature_disabled`); `strictRateLimit` 20/min; text length <= 2,000 and sanitised; the generated text uses **only** product facts (name, category name, confirmed brand, material, country of origin, dimensions, weight, confirmed custom attributes) and never claims features that are not in the data.
   * `concise`: 1-2 sentences following the design sample: "Explore the {name} in our {category} collection. Review the product details to find out whether it suits your {category keyword} needs." (category keyword = first word of the category name, lower-case; omit the clause when there is none).
   * `benefits`: a short intro plus bullets built **only from existing facts** (e.g. "Material: Canvas", "Made in India", "Dimensions: 50 x 30 x 25 cm", "Weight: 1.2 kg"); when no facts besides name/category exist return a generic sentence with `needsFacts: true` and note "Based on the product name and category only. Add verified features before highlighting specific benefits."
   * `rewrite`: deterministic clean-up of the provided text (whitespace, capitalisation of sentences, repeated punctuation, duplicate sentences removed, trim to <= 2,000 characters at a sentence boundary); 409 `nothing_to_rewrite` when there is no text; `unchanged: true` when nothing improved.
   * `note` is the grounding line shown under the preview.
2. `POST /products/{id}/ai/description/{suggestionId}/apply { version }` (optimistic lock; writes description + descriptionHtml through the same code path as a normal save; marks `applied`; audit `product.ai_description_applied`; returns the creation DTO) / `POST .../dismiss` (marks `dismissed`; idempotent) / `GET /products/{id}/ai/description?limit=` (latest suggestions). Suggestions older than 7 days cannot be applied (409 `suggestion_expired`). A suggestion can be applied once (409 `already_decided`).
3. Provider interface (`DescriptionProvider.generate(input) -> text`) with the rules provider as default; no network calls in this package.

### Work package IMAGES (owner: `modules/documents/**`)
1. `POST /products/{id}/documents/placeholder` (documents:write) -> creates a **placeholder image** document (`isPlaceholder: true`, status `uploaded`, SVG generated server-side: neutral background, the product code initials in large type, small "Image required" caption; deterministic for the same product; max 1 placeholder per product, idempotent) and makes it primary only when the product has no real primary. 409 `has_primary_image` when a real primary exists.
2. Replacing: confirming/uploading the first **real** image while the primary is a placeholder makes the new image primary and soft-deletes the placeholder. A placeholder is never kept next to real images.
3. Image validation on upload/confirm: magic-byte MIME check (jpeg, png, webp, gif) must match the declared type (else `rejected`, 422 `mime_mismatch`); parse width/height from the headers (no external libraries available: write small, safe parsers with bounds checks); store `width` / `height`; shorter side < 200 px -> rejected (422 `image_too_small`); longer side < 1000 px -> accepted with `warnings: ['low_resolution']` in the document DTO; decompression-bomb guard (pixels > 100 megapixels -> rejected); max 20 product images per product (409 `image_limit`).
4. Cancel upload: `DELETE /documents/{id}` on a `pending_upload` document removes the record and any partial object, idempotent; also add `POST /documents/{id}/cancel` as an alias returning `{ cancelled: true }`.
5. First confirmed real image becomes primary automatically (verify and test; fix if the existing code only sets primary in some paths); setting another image primary keeps the unique-primary invariant.
6. Serving: placeholders are served with `Content-Type: image/svg+xml`, `X-Content-Type-Options: nosniff`, `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'; sandbox`, and `Content-Disposition: inline`; **user-supplied SVG remains rejected** (not in the MIME allow-list).
7. DTO: add `isPlaceholder`, `width`, `height`, `warnings` to the document schema (additive). `GET /products/{id}/primary-image` -> `{ state: 'none'|'uploading'|'placeholder'|'ready', document: DTO|null }` using the same definition as section 3.
